auto-rtt-viewer / 시험 절차

시험 절차

pytest 단위 테스트와 Sound1 실보드 통합 테스트로 요구사항 AC1~AC9를 회귀 검증합니다.

1. 단위 테스트 (하드웨어 불필요)

cd path\to\auto-rtt-viewer
.venv\Scripts\activate
pytest tests/ -v

예상 결과: 모든 테스트 통과.

검증 범위:

  • test_config.py — YAML 로드, fixed mode 주소 누락 시 ValueError, 16진수 문자열 주소, 선택적 override
  • test_pipeline.py — Dispatcher fan-out, 타임스탬프 라인별 부착, 부분 라인 버퍼링
  • test_telnet_iac.py — Telnet IAC 제어 시퀀스 제거 (WILL/DO/escaped FF/SB..SE)
  • test_connector.py — pylink mock 기반 재시도 루프, SN 기억, CB 스냅샷 비교

2. 통합 시험 (실제 보드 연결)

사전 조건

  • Sound1 보드에 펌웨어 플래싱 완료
  • J-Link 프로브 연결
  • Windows PC에 SEGGER J-Link SW 설치

2.1 AC1 — 최초 연결 ≤ 1초

auto-rtt-viewer --timestamp

판정:

  • 실행 후 첫 RTT 라인이 1초 이내 출력되어야 한다.
  • [AUTO-RTT] HH:MM:SS.mmm INFO RTT 연결 완료 ... 메시지 확인.

2.2 AC2 — 전원 OFF → ON 시 초기 메시지 누락 없음

  1. auto-rtt-viewer --timestamp 실행 중.
  2. 보드 전원 OFF → 3초 대기 → ON.
  3. 출력 관찰.

판정:

  • 전원 OFF 시: WARN 연결 끊김. 재연결 시도 중. 표시.
  • 전원 ON 후 1초 이내 INFO RTT 연결 완료 재표시.
  • 부팅 메시지(부트로더가 rtt_printf로 찍는 첫 라인)가 라인 단위로 누락 없이 표시되는지 확인 (펌웨어 로그 내용을 사전에 알고 있어야 함).

2.3 AC3 — 로그 파일 무손실 기록

auto-rtt-viewer --logfile logs\ac3.log
  1. 전원 OFF / ON을 3회 반복.
  2. Ctrl+C 종료 후 logs\ac3.log 내용 검사.

판정:

  • stdout에 찍힌 모든 라인이 파일에도 존재.
  • 재연결 경계에서도 상태 메시지([AUTO-RTT] ... WARN 연결 끊김 ...)가 파일에 기록.

2.4 AC4 — Telnet 출력 확인

  1. auto-rtt-viewer 실행.
  2. TeraTerm에서 Telnet 127.0.0.1:19021 접속.
  3. 타겟이 새 RTT 라인을 찍을 때 TeraTerm에도 동시에 표시되는지 확인.

판정: stdout과 TeraTerm에 동일 내용이 표시.

2.5 AC5 — Telnet 키 입력이 타겟에 전달

  1. TeraTerm에서 접속 중.
  2. 펌웨어가 기대하는 명령어(예: Sound1 UI 명령어 중 하나)를 입력 후 Enter.
  3. 타겟 펌웨어의 응답 메시지가 출력되는지 확인.

판정: 타겟이 해당 명령을 수행하거나 응답을 출력.

Note
Sound1 펌웨어의 UI 명령어 목록은 Sound1 프로젝트 자체 문서를 참조합니다.

2.6 AC6 — stdin 키 입력이 타겟에 전달

auto-rtt-viewer --no-telnet  # stdin은 기본 켜짐
  1. 터미널에 명령어 입력 후 Enter.
  2. 타겟 응답이 stdout에 나오는지 확인.

판정: 타겟이 해당 명령 수행.

2.7 AC7 — Sound1 기본 프로파일 즉시 동작

옵션 없이 auto-rtt-viewer만 실행하여 위 AC1~AC6가 동일하게 성립해야 한다.

2.8 AC8 — Ctrl+C 정상 종료

  1. auto-rtt-viewer 실행.
  2. Ctrl+C 입력.

판정:

  • 프로세스가 10초 이내 종료.
  • 재실행 시 "Could not open J-Link / 프로브 점유 중" 에러가 없어야 함 (= 자원 정리 정상).
  • 로그 파일이 있다면 마지막 라인이 잘리지 않고 완결된 상태.

2.9 AC9 — 상태 메시지에 타임스탬프 + prefix

--timestamp 없어도 상태 메시지는 EventBus가 자체 타임스탬프를 포함하므로:

[AUTO-RTT] 14:32:01.234 INFO  RTT 연결 완료 (...)
[AUTO-RTT] 14:32:15.891 WARN  연결 끊김. 재연결 시도 중.
[AUTO-RTT] 14:32:16.012 INFO  RTT 연결 완료 (...)

판정: [AUTO-RTT] HH:MM:SS.mmm LEVEL 메시지 형식 준수.

3. 회귀 시험 체크리스트

변경 커밋 후 최소 아래 항목 확인:

  • [ ] pytest tests/ 전부 통과
  • [ ] auto-rtt-viewer --version 동작
  • [ ] auto-rtt-viewer --help 메시지에 모든 옵션 표시
  • [ ] 보드 연결 상태에서 AC1~AC2 관찰
  • [ ] Ctrl+C 종료 후 재실행 시 J-Link 점유 충돌 없음

4. 알려진 한계

  • raw 모드 stdin: Windows에서 write.mode: raw는 현재 line 모드와 동일하게 동작 (키 즉시 전송 미지원). 차후 msvcrt.getch 기반 확장 필요 시 이슈 기록.
  • 멀티 클라이언트 Telnet 입력 충돌: 동시에 두 클라이언트가 입력하면 바이트가 섞일 수 있음 (도착 순으로 직렬화만 보장). 실제 운용에서는 단일 클라이언트 권장.
