auto-rtt-viewer / 트러블슈팅

트러블슈팅

증상별로 빠르게 원인과 조치를 찾을 수 있게, 설치·실행·연결·출력·입력·인코딩 각 영역의 트러블슈팅을 한 페이지에 모았습니다.

1. 설치·환경 문제

증상원인 / 해결
Activate.ps1 파일을 로드할 수 없습니다 설치 §2.2의 실행 정책 설정이 안 되어 있음. 또는 일회성 우회로 .\.venv\Scripts\auto-rtt-viewer.exe 직접 호출 가능.
[.dev] is not a valid editable requirement 설치 §2.3 명령의 따옴표·점 위치 오타. 정답: pip install -e ".[dev]"
프롬프트에 (.venv)가 안 뜸 설치 §2.4의 Python: Select Interpreter 설정이 안 되어 있거나, 터미널을 그 설정 전에 열어둠. 터미널을 닫고 새로 엽니다.
auto-rtt-viewer: command not found venv가 활성화되지 않은 상태. 프롬프트에 (.venv)가 있는지 먼저 확인.
auto-rtt-viewer --version이 동작 안 함 pip install -e ".[dev]"가 실패했을 가능성. pip list로 auto-rtt-viewer 표시되는지 확인 후 재설치.

2. 연결 문제

증상원인 / 해결
JLinkException: Could not open J-Link J-Link SW 미설치, 또는 JFlash·RTT Viewer GUI·Ozone 등 다른 프로그램이 프로브를 점유 중. 사용법 §4 참고 — 다른 도구 종료 후 자동 재연결됨.
JLinkException: Target system has no power. 타겟 보드 전원이 꺼져 있음. 전원 인가하면 자동 재연결.
target_connected()=False SWD 결선·전원 공급 확인. --speed 500처럼 속도를 낮춰 재시도.
RTT Control Block not found 펌웨어가 RTT 초기화를 안 했거나 주소가 다름. 프로파일의 cb_search를 auto 또는 range로 바꿔서 재시도.
SEGGER J-Link 선택창이 매 실행마다 뜸 프로세스 재실행 시에는 정상 (SN 기억이 휘발). --serial <SN>으로 고정 지정하면 됨. 같은 프로세스 내에서 매번 뜬다면 첫 연결이 _remember_serial에 도달 못한 경우.
WARN 지정 SN=... 열기 실패 → 기본 선택으로 fallback 세션에 기억된 SN의 프로브가 더 이상 PC에 연결되어 있지 않음. 자동으로 SEGGER 기본 동작으로 넘어가므로 추가 조치 불필요.

3. 로그·출력 문제

증상원인 / 해결
아무 로그도 안 나옴 디버깅 §9.1 체크리스트 참고. 순서: venv 활성화 → --version 동작 → J-Link USB → SEGGER SW 설치 → --speed 1000 저속 시도 → 점유 충돌 확인.
부트로더 로그는 나오는데 앱 로그가 안 나옴 디버깅 §9.2 참고. RTT CB 변경 감지 + RTT 버퍼 변경 로그가 떴는지 확인. 안 떴다면 cb_search.mode=auto인지 확인 (fixed여야 감지 가능).
연결 끊김이 감지 안 됨 디버깅 §9.3 참고. cb_search.mode=fixed인지, reconnect.poll_interval_ms가 너무 크지 않은지 확인.
같은 에러가 계속 도배됨 30초 요약 전이라면 정상 — 스팸 억제는 30초마다 1회 요약. 디버깅 §9.4 참고.
로그 파일이 자라지 않음 --logfile PATH로 명시했는지 확인. 경로의 폴더는 자동 생성되지만 파일 쓰기 권한이 없으면 실패.

4. 입력 문제

증상원인 / 해결
TeraTerm에서 키를 쳐도 타겟이 반응 안 함 펌웨어가 downchannel 0을 읽고 있는지, 프로파일의 write.line_terminator가 펌웨어 파서의 기대와 맞는지 확인.
VSCode 터미널 입력이 타겟에 안 들어감 --no-stdin이 지정되어 있는지 확인. 기본은 stdin 켜짐.
TeraTerm 접속 자체가 안 됨 auto-rtt-viewer가 실행 중인지 확인. --no-telnet이 지정되어 있는지 확인. 포트를 바꿨다면 (--telnet-port) 그 포트로 접속.
raw 모드 입력이 즉시 안 보내짐 (Windows) 현재 Windows에서 write.mode: raw는 line 모드와 동일하게 동작 (알려진 한계). Enter 입력 시점에 전송됨.

5. 인코딩 문제

증상원인 / 해결
한글이 ���� 로 깨짐 PowerShell 기본 cp949. 터미널에서 한 번 chcp 65001 실행. 영구 적용은 설치 §4의 VSCode settings.json 터미널 프로파일 설정 참고.

6. 종료 문제

증상원인 / 해결
Ctrl+C 누른 후 한참 안 끝남 RTT close + Telnet 정리 등으로 수 초 소요될 수 있음. 10초 이상이면 비정상 — issue 보고 권장.
재실행 시 "프로브 점유 중" 에러 이전 프로세스가 비정상 종료해 J-Link DLL 핸들이 남아있는 경우. Windows 작업 관리자에서 좀비 python 프로세스 확인 후 강제 종료. SEGGER J-Link Commander 자체를 다시 실행해도 정리 가능.
로그 파일 마지막 라인이 잘림 비정상 종료(예: 프로세스 강제 kill). 정상 Ctrl+C면 플러시 보장.

7. 테스트 / 회귀 문제

증상원인 / 해결
pytest tests/ 실패 실패한 테스트 이름을 보고 범위 좁힘 — tests/test_connector.py::test_xxx 단독 실행. 회귀라면 직전 커밋과 diff 비교.
pytest-asyncio 관련 경고 pyproject.toml의 asyncio_mode = "strict"가 적용되도록 pip install -e ".[dev]" 재설치.
