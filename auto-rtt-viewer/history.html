이력과 변경

auto-rtt-viewer 첫 개발의 단계 진척, 시계열 로그, 핵심 결정, 후속 영향, 그리고 초기 main 라인 이후 누적된 동작 영향 커밋과 문서 동기화 커밋 목록을 정리합니다.

3. 완료 요약

  • 기간: ~2026-04 (구체 시작일 미기록)
  • 모듈/태그: core / rtt, jlink, python, asyncio
  • 브랜치: 초기 개발 브랜치 (main 라인 형성)
  • 병합: 본 도구의 main 라인이 이미 동작 중 — 초기 개발 시점의 git 이력은 claude_main 분기 참조
  • 연계 작업: → Sound1 (펌웨어 개발 시 RTT 모니터링에 상시 사용)

4. 무엇을 했는가

J-Link RTT 출력을 자동 연결·자동 재연결로 읽어 표준 출력/파일/Telnet으로 퍼블리시하는 CLI 유틸리티(auto-rtt-viewer)를 Python 3.10 + pylink-square + asyncio + YAML 기반으로 구현. SEGGER J-Link RTT Viewer GUI를 대체. 타겟 보드(Sound1 등) 전원 OFF→ON 시 사용자가 RTT를 수동 재연결할 필요 없이 자동 복구. 기본 출력은 stdout, 옵션으로 stdin 입력 + 파일 + Telnet 서버.

5. 핵심 결정

  • 언어/스택: Python 3.10 + pylink-square(SEGGER J-Link 공식 wrapper) + asyncio + PyYAML — 빠른 시작·라이브러리 성숙도·교차 플랫폼.
  • 모듈 분할: main(엔트리·CLI 파싱) / config(YAML 설정) / core(RTT 폴링·재연결 FSM) / server(Telnet 출력) — 책임 분리로 단위 테스트 용이.
  • 재연결 전략: 타겟 RAM의 SEGGER_RTT Control Block을 SWD 폴링하다가 read 실패 시 일정 backoff 후 재연결. 보드 전원 OFF 시점부터 ON 후 첫 메시지까지 사용자 개입 없이 복구.

6. 후속 영향

  • Sound1 펌웨어 개발의 RTT 모니터링 표준 도구로 정착.
  • 다른 MCU 타겟도 YAML 설정만 바꿔 재사용 가능 — 본 도구의 핵심 가치.
  • docs 컨벤션 마이그레이션 후 사용방법/에 사용법·디버깅 가이드·시험 절차가 모이고 참고/J-Link/에 도메인 지식이 보존됨.
  • wiki 프로젝트로 1차 가공을 거치며 본 HTML 사이트가 외부 공개 가능 형태로 재구성됨.

7. 누적 동작·문서 커밋 (claude_fix-disconnect-detection 브랜치 13 커밋)
