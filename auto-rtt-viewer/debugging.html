디버깅 가이드

실행 중 관찰되는 현상의 근거를 코드와 연결하고, 각 주요 기능의 동작 원리·호출 순서·실패 처리를 한 페이지에 모은 run-time 진단 맵입니다. 다른 세션(사람 또는 AI)이 즉시 컨텍스트를 잡고 디버깅에 착수할 수 있도록 작성되었습니다.

1. 문서 목적

  1. 실행 중 관찰되는 현상(로그·동작)의 근거를 코드와 연결.
  2. 각 주요 기능의 동작 원리·호출 순서·실패 처리를 한 곳에 요약.
  3. 트러블슈팅 시 확인할 포인트를 바로 찾을 수 있게.
  4. 최근 변경 이력을 남겨 "지난번에 뭐가 바뀌었지?"를 추적.

2. 현재 구현 상태 (TL;DR)

큐 의미

  • out_queue (bytes): 타겟에서 읽은 RTT up 바이트 + EventBus 상태 메시지가 합쳐지는 단일 큐. 각 sink가 복제 소비.
  • in_queue (bytes): Telnet/stdin이 보낸 호스트→타겟 바이트. RttWriter가 소비해 down channel에 write.

pylink 동기 호출은 전부 asyncio.to_thread()로 오프로드 — 이벤트 루프 블로킹 방지.

4. 런타임 흐름 — 연결부터 종료까지

4.1 전체 상태 머신

stateDiagram-v2
    [*] --> Connecting
    Connecting --> Connecting: _connect 실패 (retry_interval_ms 후 재시도)
    Connecting --> Connected: _connect OK + _rtt_start OK + _snapshot_and_log_cb OK
    Connected --> Disconnected: supervise return

4.2 JLinkConnector.run() 골격

while True:
    jlink = _connect()            # (1)
    if jlink is None:
        sleep(retry_interval); continue

    _rtt_start(jlink)             # (2) CB 검색 (mode에 따라 fixed/auto/range)
    _events.info("RTT 연결 완료 ...")
    _snapshot_and_log_cb(jlink)   # (3) CB 스냅샷 → 로그 (첫/유지/변경)

    tasks = [reader, writer, supervisor]
    wait FIRST_COMPLETED
    cancel pending; teardown jlink
    _events.warn("연결 끊김. 재연결 시도 중.")

(1) _connect:

  • _open_jlink(jlink) — SN 선택 로직 (§5.1)
  • jlink.set_tif(SWD|JTAG) + jlink.connect(device, speed)
  • target_connected() sanity check
  • 성공 시 _remember_serial() + _reset_fail_state()
  • 실패 시 _emit_connect_failure(exc) (§5.3) + 리턴 None

(2) _rtt_start:

  • fixed → jlink.rtt_start(cb.address) (Sound1 = 0x20000000)
  • range → SetRTTSearchRanges exec 후 rtt_start()
  • auto → 인자 없이 rtt_start()

(3) _snapshot_and_log_cb:

  • CB 주소가 있으면(_probe_address()) 헤더 24B + aUp[N](24B×N) + aDown[M](24B×M) 읽어 파싱.
  • _last_cb_snapshot 대비 첫 연결 / 유지 / 변경 중 하나 로그.
  • 스냅샷을 _last_cb_snapshot에 갱신 → §5.4의 supervise baseline 역할.

4.3 동시 태스크 3개

태스크종료 조건종료 시 의미
rtt-readerrtt_read 예외SWD/RTT I/O 오류 → 연결 끊김으로 간주
rtt-writerrtt_write 예외동상

5. 주요 기능 동작 세부

5.1 J-Link 선택 (SN 세션 기억)

선택 우선순위 (_open_jlink):

  1. cfg.target.serial_no — CLI --serial 또는 프로파일 YAML target.serial_no.
  2. self._session_sn — 같은 프로세스 내 이전 연결에서 기억한 SN.
  3. (없음) → pylink.JLink.open() — 장치 1개면 자동, 2개 이상이면 SEGGER 선택 창.
preferred = self._cfg.target.serial_no or self._session_sn
if preferred: jlink.open(serial_no=preferred)   # 실패 시 warn + jlink.open() fallback
else:         jlink.open()

기억(_remember_serial):

  • 연결 성공 직후 jlink.serial_number 읽어 self._session_sn에 저장.
  • 이전 값과 다를 때만 INFO J-Link SN=... 기억 발행.
  • 파일 저장 없음. Ctrl+C 종료 = 기억 휘발.
sequenceDiagram
    participant U as 사용자
    participant A as auto-rtt-viewer
    participant P as pylink
    Note over A: 실행 시작 (_session_sn=None)
    U->>A: auto-rtt-viewer
    A->>P: open()  (SN 미지정)
    P-->>U: SEGGER 선택창 (2개 이상일 때만)
    U->>P: SN=123456789 선택
    P-->>A: open OK
    A->>P: serial_number
    P-->>A: 123456789
    A->>A: _session_sn = 123456789
    Note over A: 전원 OFF/ON, JFlash 등으로 재연결 트리거
    A->>P: open(serial_no=123456789) → 선택창 없이 즉시 열림

관련 파일: connector.py _open_jlink / _remember_serial.

5.2 연결 끊김 감지 이중화

target_connected()만 폴링하면 J-Link DLL 내부 캐시 때문에 전원 OFF를 즉시 감지 못 하는 경우가 있음 (RTT 메커니즘 §2). 보강:

every poll_interval_ms (기본 100 ms):
    if not target_connected: disconnect
    if probe_addr: memory_read32(probe_addr, 1)  # SWD 무응답이면 여기서 예외
  • probe_addr = cb_search.mode=fixed → address, mode=range → start, mode=auto → None (이 경우 보강 미적용).
  • Reader/Writer도 예외를 잡아 events.warn("RTT 읽기/쓰기 실패 (...)") 발행 후 re-raise → 태스크 종료 → 메인 루프 재연결.

관련 파일: connector.py _supervise / _probe_address, rtt_io.py.

5.3 연결 실패 이벤트 스팸 억제

보드 전원 OFF 상태에서 재시도 간격(100 ms)마다 같은 WARN이 반복 찍히는 문제를 막는다.

조건동작
첫 실패WARN 연결 실패: <사유>
같은 사유 반복조용히 카운트만
같은 사유 유지 + 30초 경과WARN 연결 실패 지속 (N회 동안 같은 사유) — 최근: ...
사유 변경즉시 새 WARN 연결 실패: <새 사유>
연결 성공_reset_fail_state() → 다음 실패는 다시 "첫 실패" 취급

상수: FAIL_SUMMARY_INTERVAL_S = 30.0 (connector.py:16).

관련 파일: connector.py _emit_connect_failure / _reset_fail_state.

5.4 CB 스냅샷 + 실시간 변경 감지

목적: 부트로더→앱 전환처럼 연결이 유지된 채 타겟이 _SEGGER_RTT.aUp[] 내용을 바꾸면 pylink의 내부 캐시(rtt_start 시점의 버퍼 메타)가 stale이 됨 → 새 채널의 데이터를 못 읽게 됨. 이를 자동 감지해 rtt_start를 다시 호출하도록 강제.

CB 레이아웃 (Cortex-M 32-bit, little-endian):

offset  0..15 : acID[16]                 "SEGGER RTT\0\0\0\0\0\0"
offset 16..19 : MaxNumUpBuffers   (int32)
offset 20..23 : MaxNumDownBuffers (int32)
offset 24 .. : aUp[N]   — 각 24바이트 (sName, pBuffer, SizeOfBuffer, WrOff, RdOff, Flags)
                                                         ↑ 스냅샷 대상 3개 필드
offset 24 + N*24 .. : aDown[M]  — 각 24바이트 (동일 레이아웃)

비교 대상: aUp[i].pBuffer, SizeOfBuffer, Flags / aDown[i] 동일. (WrOff/RdOff는 runtime 변동 값이라 제외.)

두 시점에서 CB를 읽음:

시점함수결과
연결 성공 직후_snapshot_and_log_cb첫 연결 / 유지 / 변경 로그 + _last_cb_snapshot 갱신
연결 유지 중 (100 ms 주기)_supervise가 _read_cb_snapshot 재호출 후 baseline 비교다르면 WARN RTT CB 변경 감지 — pylink 캐시 refresh 위해 재연결 (변경점: ...) + return

supervise가 return하면 메인 루프 → teardown → reconnect → _rtt_start 재호출 → pylink 내부 버퍼 캐시가 새 주소로 갱신되고 _snapshot_and_log_cb가 변경: 로그 한 줄 더 남김.

sequenceDiagram
    participant BL as Bootloader
    participant APP as App (CM3)
    participant CB as _SEGGER_RTT (0x20000000)
    participant SV as supervise (host)
    participant RS as run (host)

    BL->>CB: _DoInit (aUp[0] 세팅)
    Note over SV: _last_cb_snapshot = {up[0]=0xA..}
    SV->>CB: 100 ms마다 read → 변화 없음
    BL->>APP: jump
    APP->>CB: SEGGER_RTT_ConfigUpBuffer(1, ...)
    APP->>CB: aUp[1] 세팅 (0xB..)
    SV->>CB: 다음 폴링 read
    SV->>SV: baseline != current → WARN + return
    RS->>RS: teardown + reconnect + _rtt_start
    Note over RS: pylink 캐시 refresh → 앱 채널 정상 수신

cb_search.mode=auto는 CB 주소를 모르므로 이 보강이 적용되지 않는다. Sound1 기본은 fixed 0x20000000이라 해당 없음.

관련 파일: connector.py _snapshot_and_log_cb / _read_cb_snapshot / _parse_buffers / _format_cb_diff / _supervise.

5.5 재연결 사이클

재연결 트리거 6가지 — 모두 동일한 경로(teardown → while True top → _connect)로 수렴.

트리거주된 원인
target_connected()=False타겟 전원 OFF, SWD 결선 불량
memory_read32(probe_addr) 예외전원 OFF 중 SWD 무응답
rtt_read/write 예외RTT CB 파괴, 타겟 MCU halt 등
CB 스냅샷 변경 감지부트로더→앱 재구성, 앱이 ConfigUpBuffer 호출
_rtt_start 예외CB 자동 검색 실패 (pylink #249 등)
_connect 단계 예외J-Link DLL 다른 프로세스 점유(JFlash), USB 분리 등

재연결 간격 = reconnect.retry_interval_ms (기본 100 ms). 무한 재시도(max_retries: -1).

9. 진단·트러블슈팅 체크리스트

9.1 "아무 로그도 안 나옴"

  1. (.venv) 활성화? 프롬프트 확인.
  2. auto-rtt-viewer --version 실행되는지.
  3. J-Link 프로브 USB 연결 상태.
  4. JLinkARM.dll이 PATH에 있는지 (SEGGER SW 설치 확인).
  5. auto-rtt-viewer --speed 1000 같은 저속으로 시도.
  6. 다른 프로그램(JFlash / RTT Viewer GUI / Ozone)이 프로브 점유 중인지.

9.2 "부트로더 로그는 나오는데 앱 로그가 안 나옴"

우선 로그를 보고 어느 시점인지 판단:

  • RTT CB 변경 감지 메시지가 한 번은 뜨고 그 뒤에 RTT 버퍼 변경: ...도 떴는가?
    • 예: 자동 refresh 정상 동작 중. 그래도 앱 로그가 없다면 앱이 up channel 0이 아닌 다른 채널에 쓰는지, 또는 앱이 실제로 write를 하는지 확인.
    • 아니오: CB 변경이 감지되지 않음. cb_search.mode=auto로 설정되어 있는지 프로파일 확인. fixed여야 감지 가능.
  • up_channel 설정이 앱이 쓰는 채널과 일치하는지. 프로파일의 rtt.up_channel vs 앱 코드의 SEGGER_RTT_Write(N, ...).
  • CB 주소가 실제와 다른지. jlink.memory_read8(0x20000000, 16) 결과가 "SEGGER RTT\0\0\0\0\0\0"인지 확인 필요 (현 도구는 직접 노출 API 없음 — 수동 진단이면 SEGGER J-Link Commander에서 mem 0x20000000 0x100 참고).

9.3 "연결 끊김이 감지 안 됨"

  • cb_search.mode=fixed인지 (auto/range는 부분 감지만).
  • reconnect.poll_interval_ms 값(100 ms). 너무 크게 설정되지 않았는지.
  • target_connected 자체가 False를 반환 안 해도 memory_read32가 예외를 던지므로 둘 중 하나는 걸려야 함. 둘 다 "통과"해서 끊김을 놓치는 경우는 SWD가 여전히 살아있다는 뜻.

9.4 "같은 에러가 계속 도배됨"

  • 30초 요약 전이라면 정상. 31초 이상 지나도 새 WARN이 끊임없이 뜨면 _emit_connect_failure의 dedup 상태가 초기화되는 경로를 확인 (_reset_fail_state는 _connect 성공 시에만 호출됨).

9.5 "J-Link 선택창이 매번 뜸"

  • 같은 프로세스 내에서는 첫 연결 이후 뜨지 않아야 함. 뜬다면 _open_jlink가 self._session_sn을 못 읽는 상태 — 이전 연결이 _remember_serial에 도달 못했을 가능성 (연결 직후 실패).
  • 프로세스 재실행에서는 뜨는 게 정상. 기억이 휘발했기 때문. --serial <SN>으로 고정 지정 가능.

9.6 테스트로 확인

.venv\Scripts\python.exe -m pytest tests/ -v

전부 통과가 안 나오면 회귀. tests/test_connector.py의 개별 테스트로 범위 좁힘.

10. 알려진 한계 / 향후 개선 아이디어

  • cb_search.mode=auto 프로파일은 CB 변경 감지 미적용. 현재 Sound1 기본은 fixed라 해당 없음.
  • CB 스냅샷 refresh가 teardown을 경유하므로 J-Link close/open이 매번 일어남 (수백 ms). 이상적으로는 rtt_stop + rtt_start만 재호출하는 inner-loop refresh가 더 가볍지만 reader/writer 라이프사이클 관리 복잡도가 늘어나 현재 채택하지 않음.
  • 다중 up channel 병합 수신 미지원. 필요해지면 config.rtt.up_channels: [0,1] 스펙 확장 + RttReader를 채널당 인스턴스화 + 라인 prefix 옵션 추가.
  • Windows PowerShell 기본 코드페이지 cp949 때문에 한글 메시지가 깨질 수 있음. 현재는 chcp 65001 또는 VSCode terminal profile로 우회 중.
  • J-Link Remote Server를 통한 다중 클라이언트 공유 미지원. 현재는 SEGGER DLL 단일 프로세스 전제.
