auto-rtt-viewer / 요구사항

요구사항

auto-rtt-viewer의 목표 G1~G6, 기능 요구사항 F1~F12, 비기능 NF1~NF6, 수용 기준 AC1~AC9, 작업 범위 외 항목, 위임 범위를 한 페이지에 정리합니다.

1. 배경

  • J-Link RTT Viewer(GUI)는 타겟 보드 전원이 OFF되면 연결이 끊어지고, 매번 사용자가 수동으로 재연결 버튼을 눌러야 한다.
  • Sound1(E8300) 개발 중 보드 전원 on/off가 잦은 환경에서, 이 반복 작업은 개발 흐름을 끊고 비효율적이다.
  • RTT 텍스트 출력은 TeraTerm 또는 VSCode 터미널에서 보는 것이 익숙하므로, 별도 GUI 없이 텍스트 스트림으로 소비할 수 있어야 한다.

2. 목표 (Goals)

ID내용
G1타겟 보드 전원 상태와 무관하게 RTT 연결을 자동 유지·자동 복구
G2RTT 출력을 TeraTerm 또는 VSCode 터미널에서 실시간으로 읽기
G3필요 시 파일로 영구 로그 저장
G4Sound1(E8300) 기본 프로파일 포함 — 별도 설정 없이 즉시 사용
G5설정 파일 교체만으로 다른 타겟 MCU에도 재사용 가능
G6기존 J-Link RTT Viewer GUI를 완전히 대체

3. 기능 요구사항 (Functional Requirements)

ID요구사항비고
F1J-Link에 자동 연결 (칩명, 인터페이스, 속도 설정 기반)—
F2연결 끊김을 이벤트 + 폴링 이중화로 감지안정성 확보
F3끊김 감지 시 최대한 빠르게 자동 재연결. 재시도 주기·최대 시도 횟수 설정 가능 (기본값은 공격적으로 짧게)AC2 참조
F4지정된 RTT 업채널(기본 0번)을 읽어 출력다중 채널은 확장 고려
F5stdout에 실시간 출력 (VSCode 터미널용)기본 활성
F6파일 로깅 옵션 — 경로 지정, append 모드—
F7Telnet 서버 모드 — 지정 포트에서 실시간 스트림 송출 (TeraTerm telnet localhost <port> 접속용)—
F8설정 파일 (YAML or JSON) 기반 타겟 구성 — chip, interface, speed, RTT 검색 영역 등—
F9Sound1(E8300) 기본 프로파일 포함 — 즉시 사용 가능—
F10각 출력 라인에 타임스탬프 prefix 옵션on/off
F11상태 메시지(연결/끊김/재시도/복구)는 RTT 데이터와 시각적으로 구분색상 또는 prefix
F12Host → Target ASCII 키 입력 (RTT downchannel 쓰기) — 입력 소스: (a) Telnet 클라이언트(TeraTerm), (b) 프로세스 stdin(VSCode 터미널). 두 경로 동시 활성 가능양방향 RTT

4. 비기능 요구사항 (Non-Functional)

ID요구사항
NF1Windows 10/11 지원 (Linux/macOS는 차후)
NF2SEGGER J-Link 소프트웨어 설치(JLinkARM.dll 등)를 전제로 한다
NF3설치 부담 최소화 — 가벼운 의존성 (Python venv + pip 수준)
NF4로그 경로·telnet 포트·재시도 주기 등 런타임 파라미터는 CLI 인자 또는 설정 파일로 변경 가능
NF5Ctrl+C 종료 시 J-Link 연결 해제, 파일 플러시, 소켓 닫기 등 자원 정리 보장
NF6빌드·실행 절차는 사용방법 문서로 정리

5. 수용 기준 (Acceptance Criteria)

ID기준
AC1도구 실행 시 보드 전원이 켜져 있으면 1초 이내 RTT 출력이 stdout에 나타난다.
AC2보드 전원 OFF → ON 시, 사용자 조작 없이 펌웨어의 RTT 초기화 직후 첫 메시지부터 누락 없이 캡처된다. 재연결 지연 목표: 1초 이내.
AC3파일 로깅 옵션 활성 시, RTT 출력 전체가 누락 없이 파일에 기록된다 (재연결 경계에서도 유실 없음).
AC4Telnet 서버 모드 활성 시, TeraTerm에서 telnet localhost <port>로 접속해 실시간 출력을 볼 수 있다.
AC5Telnet 클라이언트가 송신한 ASCII 키 입력이 타겟 펌웨어에 전달된다 (RTT downchannel).
AC6--stdin 모드(또는 동등 옵션) 활성 시, 프로세스 stdin으로 받은 ASCII 입력도 타겟에 전달된다.
AC7Sound1(E8300) 기본 프로파일로 설정 편집 없이 동작한다.
AC8Ctrl+C 입력 시 자원 정리 후 종료한다 (좀비 프로세스·락 파일 없음).
AC9연결 끊김·복구 이벤트가 타임스탬프와 함께 상태 메시지로 표시된다.

6. 회귀 방지

  • 본 작업은 별도 feature 브랜치 격리로 진행 (초기 개발 — 첫 main 라인 형성)
  • 각 commit이 atomic — 단계별 revert 가능

7. 작업 범위 외 (Out of Scope)

  • J-Link GDB 디버깅 기능 (브레이크포인트, 메모리 덤프 등)은 범위 외
  • RTT 출력의 파싱·시각화 대시보드는 범위 외 (raw 텍스트 스트림만 취급)

8. 위임 범위 (Claude 자율 결정 → 계획에서 확정)

Important
아래 항목은 요구사항 단계에서는 고정하지 않고, 아키텍처(계획)에서 근거와 함께 결정한다.
  • 구현 언어: Python 유력 (pylink-square 라이브러리 검토) vs 기타
  • J-Link 제어 방식: pylink-square (Python binding) vs JLink.exe CLI 래핑 vs 혼합
  • 설정 파일 포맷: YAML vs JSON vs TOML
  • Telnet 서버 멀티 클라이언트 지원 여부 (입력 출처가 여럿일 때 처리 규칙 포함)
  • stdin 입력 모드의 라인 버퍼링 / raw 모드 처리
  • 로그 파일 회전(rotation) 방식 — 날짜별/크기별
  • 패키지/의존성 관리: pip + requirements.txt vs poetry vs uv
  • 재연결 폴링 간격의 기본값 — 빠른 재연결(=AC2 만족)과 USB/J-Link 부하의 균형점

위임 범위 밖 (사용자 결정 영역)

  • 최종 기술 스택 승인 (Python 3.10·pylink-square·asyncio·YAML)
  • Telnet 기본 포트·라인 종결자·패키지 이름·프로파일 샘플 (계획 §12 승인 대상)
