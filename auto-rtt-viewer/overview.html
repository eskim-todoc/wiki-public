auto-rtt-viewer / 개요

개요

auto-rtt-viewer가 무엇을 해결하고, 어떤 시나리오에서 작동하며, 기존 도구와 어떻게 다른지 정리합니다.

무엇을 해결하는 도구인가

SEGGER 공식 J-Link RTT Viewer GUI는 타겟 보드 전원이 OFF되면 연결이 끊어지고, 매번 사용자가 재연결 버튼을 손으로 눌러야 합니다. Sound1(E8300) 펌웨어 개발 중에는 보드 전원 on/off가 잦아 이 반복 작업이 개발 흐름을 끊고 비효율적이었습니다.

RTT 텍스트 출력은 TeraTerm이나 VSCode 터미널에서 보는 게 익숙하므로, 별도 GUI 없이 텍스트 스트림으로 소비할 수 있어야 했습니다. auto-rtt-viewer는 이 두 요구를 하나의 Python CLI로 묶어 해결합니다.

사용 시나리오

아래는 도구가 가정하는 표준 사용 흐름입니다.

sequenceDiagram
    actor User as 사용자
    participant Tool as auto-rtt-viewer
    participant JLink as J-Link
    participant Board as 타겟 보드
    participant Term as TeraTerm / VSCode 터미널

    User->>Tool: 실행 (프로파일 지정)
    Tool->>JLink: 연결 시도
    alt 보드 전원 ON
        JLink->>Board: SWD/JTAG 연결
        JLink-->>Tool: RTT 스트림 (upchannel)
        Tool-->>Term: 실시간 출력
    else 보드 전원 OFF
        Tool->>Tool: 짧은 주기로 감지·재시도 (폴링)
    end
    Note over Board: 사용자가 보드 전원 OFF
    JLink-->>Tool: 끊김 이벤트 / 폴링 실패
    Tool->>Tool: 즉시 재연결 루프 진입
    Note over Board: 사용자가 보드 전원 ON
    Tool->>JLink: 재연결 (최대한 빠르게)
    JLink-->>Tool: RTT 스트림 재개 (초기 부팅 메시지 포함)
    Tool-->>Term: 출력 재개
    User->>Term: ASCII 키 입력
    Term->>Tool: stdin / telnet
    Tool->>JLink: RTT downchannel 쓰기
    JLink->>Board: 입력 전달
    User->>Tool: Ctrl+C
    Tool->>JLink: 연결 해제
    Tool-->>User: 종료 (자원 정리 완료)

누가 쓰는가

도구는 다음 작업을 자주 반복하는 임베디드 개발자를 1차 사용자로 가정합니다.

  • Sound1(E8300) 또는 다른 Cortex-M MCU 펌웨어 작성·디버깅
  • 보드 전원을 자주 껐다 켜야 하는 검증 작업 (캘리브레이션, 부팅 시퀀스 확인)
  • JFlash 또는 Ozone으로 빈번하게 펌웨어를 재다운로드하는 환경
  • 로그를 파일로 영구 보존하면서 동시에 라이브 모니터링이 필요한 경우
  • VSCode 터미널·TeraTerm에서 양방향 RTT 통신으로 펌웨어 콘솔에 명령을 보내고 응답을 받는 워크플로우

적용 대상

도구는 다음 타겟·환경을 검증된 1차 적용 범위로 가정합니다.

  • Sound1 (ON Semi Ezairo 8300, Cortex-M3) — 기본 프로파일 내장 (Cortex-M3 generic, SWD, 4000 kHz, CB 0x20000000 fixed)
  • 다른 Cortex-M 계열 MCU — YAML 프로파일 한 장을 추가하면 동일 도구 재사용 가능
  • Windows 10 / 11 + PowerShell + Python 3.10 이상
  • SEGGER J-Link Software Pack 설치 (JLinkARM.dll 사용)
  • SWD 또는 JTAG로 결선된 타겟 보드 + 펌웨어에 RTT 초기화 포함
Note
Linux/macOS 지원은 현재 비목표입니다. pylink-square 자체는 다중 플랫폼이지만 본 도구의 사용 절차·터미널 인코딩·실행 정책 가이드는 Windows + PowerShell + VSCode 환경 기준입니다.

왜 이 도구가 필요한가 (요약)

반복 절감
"전원 사이클 → 재연결 버튼 클릭" 루틴 자체를 제거. 도구는 켜둔 채로 보드만 만지면 됩니다.
로그 누락 0
재연결 지연이 100 ms 단위라 부트로더 초기 메시지부터 캡처. 파일 출력은 재연결 경계에서도 무손실.
개발 흐름 보존
JFlash 다운로드 → 점유 해제 → 자동 재연결까지 사람이 개입하지 않음. 새 펌웨어 부팅 로그까지 자연 연속.
재사용 가능
YAML 한 장만 추가하면 다른 타겟 MCU에도 동일 도구. 도구 자체를 다시 만들 필요 없음.
