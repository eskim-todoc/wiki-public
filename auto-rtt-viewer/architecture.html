아키텍처

Python 3.10 + pylink-square + asyncio + YAML 기반 모듈 구조, 11단계 구현 시퀀스, 끊김 감지 FSM, CB 변경 감지 메커니즘, 설정 파일 스펙, CLI 스펙, 위험 관리까지의 설계 전체.

패키지 관리venv + pip + requirements.txt (pyproject.toml 병행)설치 부담 최소.
테스트pytest + pytest-asyncio단위 테스트용. asyncio mode strict.

    Args --> Cfg --> Supervisor
    Supervisor -->|connect/rtt_start| Reader
    Supervisor -->|connect/rtt_start| Writer
    Reader --> OutQ
    OutQ --> Dispatcher
    Dispatcher --> Stdout & File & TelnetS

    Telnet --- TelnetS

  • 하나의 asyncio 루프가 모든 태스크를 운영. pylink 동기 호출은 asyncio.to_thread()로 오프로드 — 이벤트 루프 블로킹 방지.
  • Reader/Writer는 Connector가 연결 확립 후 기동. 끊김 감지 시 중단 후 재기동.
  • 모든 타겟 출력은 OutQ 하나로 수렴 → 각 Sink가 복제 소비. 입력도 InQ 하나로 수렴.
  • EventBus는 상태 메시지(연결/끊김/재시도)를 OutQ로 흘려보내 Sink에 일관된 prefix로 표시.

5. 끊김 감지 & 재연결 FSM

stateDiagram-v2
    [*] --> Connecting
    Connecting --> Connecting: 실패 (retry_interval_ms 후 재시도)
    Connecting --> Connected: connect() 성공 + target_connected() True + rtt_start() 성공
    Connected --> Disconnected: rtt_read/write 예외 발생 (이벤트형)
    Connected --> Disconnected: 주기 폴링에서 target_connected() False (폴링형)
    Connected --> Disconnected: CB 스냅샷 변경 감지
    Disconnected --> Connecting: teardown 후 즉시
    Connected --> [*]: 사용자 Ctrl+C
    Disconnected --> [*]: 사용자 Ctrl+C
  • 이벤트형 감지: Reader/Writer task가 JLinkException 포착 즉시 Supervisor에 취소 통지.
  • 폴링형 감지: poll_interval_ms (기본 100 ms) 간격으로 target_connected() + memory_read32(CB) 병행 확인.
  • CB 변경 감지: 100 ms 주기로 CB 헤더 + 버퍼 메타 비교. 변경 시 강제 재연결로 pylink 캐시 refresh.
  • 기본 retry_interval_ms = 100 ms (AC1/AC2의 1초 이내 달성 + USB 부하 적정).

6. CB 변경 감지 시퀀스 (부트로더 → 앱 전환)

sequenceDiagram
    participant BL as Bootloader
    participant APP as App (CM3)
    participant CB as _SEGGER_RTT (0x20000000)
    participant SV as supervise (host)
    participant RS as run (host)

    BL->>CB: _DoInit (aUp[0] 세팅)
    Note over SV: _last_cb_snapshot = {up[0]=0xA..}
    SV->>CB: 100 ms마다 read → 변화 없음
    BL->>APP: jump
    APP->>CB: SEGGER_RTT_ConfigUpBuffer(1, ...)
    APP->>CB: aUp[1] 세팅 (0xB..)
    SV->>CB: 다음 폴링 read
    SV->>SV: baseline != current → WARN + return
    RS->>RS: teardown + reconnect + _rtt_start
    Note over RS: pylink 캐시 refresh → 앱 채널 정상 수신

CB 레이아웃 (Cortex-M 32-bit, little-endian)

offset  0..15 : acID[16]                 "SEGGER RTT\0\0\0\0\0\0"
offset 16..19 : MaxNumUpBuffers   (int32)
offset 20..23 : MaxNumDownBuffers (int32)
offset 24 ..  : aUp[N]   — 각 24바이트 (sName, pBuffer, SizeOfBuffer, WrOff, RdOff, Flags)
                                                         ↑ 스냅샷 대상 3개 필드
offset 24 + N*24 .. : aDown[M]  — 각 24바이트 (동일 레이아웃)

비교 대상: aUp[i].pBuffer, SizeOfBuffer, Flags / aDown[i] 동일. WrOff/RdOff는 runtime 변동 값이라 제외.

Note
cb_search.mode=auto는 CB 주소를 모르므로 이 보강이 적용되지 않습니다. Sound1 기본은 fixed 0x20000000이라 해당 없음.

7. 설정 파일 스펙 (YAML)

profiles/sound1.yaml 기본 예시:

target:
  device: "Cortex-M3"          # E8300은 SEGGER 공식 미등록 → Cortex-M3 generic
  interface: "SWD"             # SWD | JTAG
  speed_khz: 4000

rtt:
  up_channel: 0
  down_channel: 0
  cb_search:
    mode: fixed                # auto | fixed | range
    address: 0x20000000        # Sound1 실측 RTT CB 주소
    # mode: auto               # 다른 타겟 재사용 시
    # mode: range
    # start:  0x20000000
    # length: 0x20000

reconnect:
  retry_interval_ms: 100       # 연결 실패 시 재시도 간격
  poll_interval_ms:  100       # target_connected() 폴링 주기
  max_retries: -1              # -1 = 무한

read:
  poll_interval_ms: 10         # RTT up 폴링 (100Hz)
  chunk_bytes: 1024

write:
  line_terminator: "\n"        # "" | "\n" | "\r\n" | "\x0A\x00" 등
  mode: line                   # line | raw

output:
  stdout: true
  logfile: null                # 경로 지정 시 활성: "./logs/rtt.log"
  timestamp: false
  event_prefix: "[AUTO-RTT]"

telnet:
  enabled: true
  host: "127.0.0.1"
  port: 19021                  # TeraTerm에서 telnet 127.0.0.1 19021
  allow_multi_client: true

9. 핵심 타입 / 인터페이스 스케치

# config.py
@dataclass
class TargetConfig:
    device: str
    interface: Literal["SWD", "JTAG"]
    speed_khz: int

@dataclass
class RttConfig:
    up_channel: int
    down_channel: int
    cb_search: CbSearch          # mode + 주소/범위

@dataclass
class ReconnectConfig:
    retry_interval_ms: int
    poll_interval_ms:  int
    max_retries: int

# (나머지 ReadConfig, WriteConfig, OutputConfig, TelnetConfig 유사)

# sinks.py
class Sink(Protocol):
    async def emit(self, chunk: bytes, meta: Meta) -> None: ...
    async def close(self) -> None: ...

# sources.py
class Source(Protocol):
    async def run(self, queue: asyncio.Queue[bytes]) -> None: ...

# connector.py
class JLinkConnector:
    def __init__(self, cfg: AppConfig, events: EventBus,
                 out_queue: asyncio.Queue, in_queue: asyncio.Queue) -> None: ...
    async def run(self) -> None: ...

13. 사용자 승인 항목 (구현 단계 게이트)

  1. Telnet 포트 19021 — SEGGER 기본값과 동일. GUI를 안 쓰므로 충돌 없음.
  2. write.line_terminator 기본값 \n — Sound1 펌웨어의 RTT 파서 기대값에 맞춰 실테스트에서 조정.
  3. 패키지명 auto_rtt_viewer — 명시적 네이밍 채택.
  4. 프로파일 기본값 — sound1.yaml 한 개만 포함 (다른 타겟 샘플은 추후 추가 시점에 결정).

14. 위험 관리

리스크가능성영향완화
E8300이 SEGGER 공식 미등록 → Cortex-M3 generic 연결 실패 가능중중연결 실패 시 상세 에러 메시지 + 설정 오버라이드 가이드, cb_search.mode: range로 fallback
rtt_start() auto-detect 실패중중Sound1은 fixed 0x20000000으로 회피. 타 타겟 재사용 시 range fallback + 사용자에게 명확히 안내
전원 ON 순간 너무 이른 connect 시도 → 타겟 부팅 전 쓰기 실패높음낮음100 ms 간격 재시도면 수 cycle 내 복구. 로그로 투명화
USB 드라이버 점유 충돌 (J-Link RTT Viewer GUI가 붙어있는 경우 등)낮음중명시적 에러 메시지 + 사용자 안내. 자동 재시도 루프로 점유 해제 시 즉시 복구
Windows asyncio Proactor vs Selector낮음낮음기본 Proactor로 동작 확인. subprocess 사용이 없어 대부분 OK
